## Пункт 1 — Точность выравнивания (канонизация + pratīka-анкоринг)

**Проблема.** Сейчас выравнивание = точное равенство нормализованных строк → счётчики `variant` (1075) и
`critical_only` (407) завышены орфографией/сандхи; сегментатор Фазы-2 ~81%, промахи маркеров (Тилака к
5.35.45 ушла в соседний). **Цель:** различать identical / variant / absent надёжно; точность привязки
комментария к стиху >95%.

**Подход.**
- Новый общий модуль **`scripts/sa_align.py`**, поверх `sanskrit_util`:
  - `canon(text)` — канонический ключ через `sanskrit_util.form_key`/`nfold`/`norm` (нейтрализует сандхи/
    висаргу/анусвару/авагbraху). ⚠️ Проверить лоссовость на ретрофлексах (в SHARED_CODE отмечен баг
    `devanagari_to_slp1` ळ→x) — при потере длины/точек оставить свой fallback-нормализатор.
  - `sim(a, b)` — `difflib.SequenceMatcher(None, canon(a), canon(b)).ratio()` (в stdlib; `levenshtein` в
    `sanskrit_util` не экспортируется).
  - `classify(a, b)` → `identical` (sim ≥ 0.95) / `variant` (0.60–0.95) / `distinct` (< 0.60).
- **`scripts/compare_editions.py`** — заменить exact-equality + replace-эвристику: (1) быстрый проход по
  `canon`-ключам для точных; (2) для несопоставленных — жадное сопоставление по `sim` с порогами; печатать
  метрики до/после. Ожидаемо: `identical`↑, `critical_only`↓ к реалистичным (<~50), `variant` — настоящие
  разночтения.
- **`scripts/extract_yellow_sargas.py`** — добавить `extract_pratika(chunk)` (первые слова глоссы до
  `iti`/данды/`--`) и привязку по содержанию: если `।।`-маркер даёт стих, чей `canon`-токен-сет не содержит
  pratīka, переприсвоить комментарий стиху, чьи слова содержат pratīka. Выводить
  `alignment_precision` = доля чанков, чья pratīka ∈ токенам назначенного стиха.

**Шаги.** (1) поставить `sanskrit_util` на PATH (`pip install -e sanskrit-util/py` или `sys.path`),
проверить import + ретрофлексы; (2) написать `sa_align.py` + мини-тест на 10 парах; (3) рефактор
`compare_editions.py`; (4) рефактор сегментатора + `alignment_precision`; (5) перегенерировать
`data/edition_comparison/` и `sundara_commentary_segmented.json`, записать `metrics_before_after.json`.

**Приёмка.** `critical_only` < ~50; `alignment_precision` сегментатора > 95% на саргах 35/36/37; Тилака к
5.35.45 привязана верно. **Риск:** лоссовая канонизация (митигируется fallback + тестом). **Эффект:**
средний. **Не изобретать:** `sanskrit_util` (SHARED_CODE §1–2).

## Пункт 3 — HTML-отчёт сравнения изданий

**Цель.** Браузерный просмотр различий (как `review.html`), без распечаток.

**Подход.** Новый генератор **`scripts/build_edition_compare_html.py`** → `data/edition_comparison/report.html`
(self-contained, встроенный JSON), переиспользуя паттерн
[`build_pilot_review_html.py`](https://github.com/gasyoun/CommentaryStrategies/blob/main/scripts/build_pilot_review_html.py).
Вход: `book_summary` + `concordance` + `significant_absences` + `critical_only_and_variants`.

**UI.** Шапка: книга-итог (66/68, +371), доп. южные сарги (№4, №8), таксономия. По сопоставленным саргам
(`per_sarga_aligned`) — секции «крит.→южн.» со счётчиками/дельтой; строки различий с цветокодом:
`identical` приглушено, `variant` — оба текста + similarity, `southern_only` зелёным (= кандидат в сноску,
с текстом), `critical_only` красным. Фильтр по типу; переход к сарге; поиск по `verse_id`.

**Шаги.** (1) генератор join+render; (2) прогон; (3) sanity (все 66 сарг + 196 runs, фильтры). **Приёмка.**
Открывается локально, показывает все различия, фильтры работают. **Эффект:** малый-средний.
**Расширяемость:** предусмотреть 3-ю колонку/режим для Гитапресса.

## Пункт 4 — Сноски о расхождениях из `significant_absences`

**Цель.** Превратить южные пассажи без критического аналога в готовые кандидаты-сноски (человеческий гейт,
как Фаза 2).

**Подход.** Новый генератор **`scripts/build_edition_footnotes.py`** → `data/edition_footnotes/candidates.json`.
- Тип: `sarga_absence` (целые доп. сарги — южн. №4, №8) · `verse_absence` (пассаж-run).
- `note_ru` в регистре ЛП **[формат на ратификацию, §3 roadmap]**, напр.:
  «Шлоки [южн. 3.20–51] (32 стиха) отсутствуют в критическом издании (Барода).»;
  для сарги — «Песнь [южн. №4] целиком отсутствует в критическом издании (Барода).»
- Якорь: первая шлока пассажа (южная нумерация).
- **Порог значимости [на ратификацию]:** минимальная длина пассажа для сноски (Костина: «значимые») —
  предлагаю ≥ 2 шлок для отдельной сноски, единичные — сводкой; целые сарги — всегда.
- **Dedup:** пропускать/помечать пассажи, где у Леонова уже есть примечание о редакции (поиск в
  `data/leonov_own_notes.json` по «критическ/южн/издани/выпал» на этих стихах), и одна сноска на пассаж,
  не на каждую шлоку.
- Каждая сноска: `review_required:true`, `source:"edition_comparison"`, provenance; гейт — расширить
  паттерн `review.html` или отдельная страница.

**Шаги.** (1) генератор runs→кандидаты с dedup против Леонова; (2) сводная статистика; (3) (опц.) вставить
в интерактивный гейт. **Приёмка.** ≤ 196 пассажей + 2 сарги → кандидаты, все `review_required`, deduped,
формат по §3. **Зависимость:** формат = §3 [ратификация]; мелкие пассажи точнее после п.1 (крупные надёжны
уже сейчас). **Эффект:** малый-средний.
